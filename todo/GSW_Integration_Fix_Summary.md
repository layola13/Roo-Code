## 🔧 修复详情

### 1. 裁判系统 - 消除"健忘裁判"Bug (Critical Fix)

**问题位置**: `src/core/task/Task.ts:4140-4180` ([`invokeJudge`](src/core/task/Task.ts:4095) 方法)

**原始缺陷**:

```typescript
// ❌ 互斥逻辑 - 只能选一个
if (有预收集证据) {
	使用预收集证据
} else if (有GSW系统) {
	查询GSW历史 // ⚠️ 永远不会执行！
}
```

**根本问题**:

- 使用 `if-else` 互斥结构
- 只要有一丁点预收集证据（哪怕只有1条），就会短路 GSW 历史查询
- 结果：裁判系统**完全无法访问跨会话的历史教训**

**修复后**:

```typescript
// ✅ 并行逻辑 - 同时使用两者
const memoryParts: string[] = []

// Part 1: 预收集证据（当前会话）
if (有预收集证据) {
    memoryParts.push(当前会话证据)
}

// Part 2: GSW历史记忆（跨会话）- 始终执行
if (有GSW系统) {
    const 历史记忆 = await queryMemory(...)
    if (历史记忆) {
        memoryParts.push(历史记忆)
    }
}

// 合并所有来源
gswHistoricalMemories = memoryParts.join('\n\n')
```

**改进效果**:

- ✅ 裁判可以同时看到"现在的证据"和"过去的历史"
- ✅ 预收集证据（<1秒）+ GSW历史查询（5-10秒）并行运行
- ✅ 支持跨会话的持续学习和错误规避

### 2. 任务对话 - 从被动到主动的智能检索 (Major Enhancement)

**问题位置**: `src/core/task/Task.ts:3116-3184` ([`getSystemPrompt`](src/core/task/Task.ts:3074) 方法)

**原始缺陷**:

```typescript
// ❌ 关键词锁死 - 过于被动
const memoryTriggerKeywords = ["上次", "之前", "记得", ...]

if (用户消息.includes(关键词)) {
    查询GSW历史  // 只有用户明确说"记得上次"才查询
}
```

**根本问题**:

- 完全依赖用户显式提及历史关键词
- 用户说"修复这个Bug"（不带关键词）→ 系统不会查找历史上是否有相关经验
- 违背了"代码演进记忆"的核心价值

**修复后**:

```typescript
// ✅ 智能触发策略 - 主动感知
const shouldQueryMemory =
    显式历史引用 ||           // 用户说"上次"（高优先级）
    任务开始/恢复 ||          // 查询架构决策和代码模式
    周期性检索                // 每10条消息自动检索一次

if (shouldQueryMemory) {
    const 历史上下文 = await queryMemory(...)
    注入到系统提示词
}
```

**改进效果**:

- ✅ **任务启动时**：自动加载相关的架构决策和代码模式
- ✅ **显式引用时**：立即响应用户的历史查询（保留原功能）
- ✅ **周期性检索**：每10条消息自动检索，保持上下文连续性
- ✅ 无需用户"提醒"，系统主动感知历史

## 🎓 技术要点

### 修复1的核心思想

- **从互斥到并行**：不再是"要么A要么B"，而是"A和B都要"
- **数据融合**：将多个来源的记忆合并为统一的上下文
- **性能优化**：预收集证据（快）先加载，GSW查询（慢）并行执行

### 修复2的核心思想

- **从被动到主动**：不等用户"提醒"，系统自己知道什么时候需要历史
- **多策略触发**：
    - 显式引用（用户说"记得"）→ 立即查询
    - 任务开始 → 加载架构决策
    - 周期性 → 每10条消息刷新一次
- **智能降级**：没有历史记忆时不影响正常工作
